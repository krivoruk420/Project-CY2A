# Руководство по разработке

## Необходимые программы

- Git для версионирования.
- Python 3.10 или новее для упаковщика и встроенных тестов.
- Blender для авторских исходников модели, когда начнётся этап 3D.
- BeamNG.drive для проверки игровых файлов; версия игры будет зафиксирована в документации тестов после выбора целевой сборки.
- Текстовый редактор для Markdown, Python и игровых конфигураций.

Установка сторонних Python-пакетов для упаковщика не требуется.

## Локальная разработка

Клонируйте репозиторий и работайте в ветке задачи:

```powershell
git clone <URL-репозитория>
cd project-cy2a
git switch -c feat/краткое-название
```

Сохраняйте источники в `references/` только в случаях, когда разрешено хранение и распространение. В `source/` размещайте авторские рабочие файлы; `.blend` не игнорируются. Файлы, предназначенные для игры, должны находиться под `game/vehicles/hirochi_cuirassier/`.

## Установка мода в BeamNG.drive

Когда появятся игровые файлы, соберите ZIP скриптом и поместите полученный архив в пользовательскую папку модов BeamNG.drive (обычно `Documents/BeamNG.drive/mods/`). Точный путь может зависеть от установки игры и пользовательских настроек. На этом этапе игровых файлов нет, поэтому устанавливаемого мода пока не существует.

## Тестирование изменений

Запустите структурные проверки:

```powershell
python -m unittest discover -s tests -v
```

Проверки упаковщика используют временные тестовые файлы и не добавляют их в каталог автомобиля. После появления мода дополнительно проверяйте запуск/перезагрузку автомобиля, сообщения игры, управление и заранее описанные сценарии повреждений. Фиксируйте версию игры, конфигурацию, шаги и наблюдаемый результат.

## Упаковка мода в ZIP

```powershell
python tools/package_mod.py
```

Успешная сборка создаёт `dist/hirochi_cuirassier.zip` с содержимым в `vehicles/hirochi_cuirassier/`. Если каталог не содержит файлов автомобиля, скрипт завершится с понятной ошибкой и не создаст пустой архив. Документы, Blender-исходники и references в архив не включаются.

## Git

- Делайте небольшие коммиты с сообщениями, описывающими изменение.
- Не коммитьте локальные логи, кэши, ZIP-сборки и секреты.
- Не переписывайте общую историю без согласования.
- Проверяйте `git status` перед коммитом и состав архива перед распространением.
- Авторские `.blend`-файлы являются исходниками и могут храниться в Git. Если их размер мешает работе, согласуйте Git LFS и зафиксируйте это до переноса файлов.
- Перед публикацией исходников, фото, чертежей или текстур проверьте права согласно `THIRD_PARTY_MATERIALS.md`.
